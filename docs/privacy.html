The Daily Reconcile.

Privacy

Last updated 6 October 2026

The Daily Reconcile is a personal newspaper. It is written each morning by a program running on its owner’s own computer, and the edition is published on this site. This page explains what the project does and does not do with data.

Reading the site collects nothing

This site is static. It has no accounts, no sign-in, no analytics and no tracking cookies, and reading it is not recorded by the project. The site is served by GitHub Pages, which keeps its own server logs under GitHub’s privacy statement; the project neither controls nor reads them. Typefaces are loaded from Google Fonts, which receives the request as part of serving them.

There is one form on the site: the newsletter sign-up, described below. Nothing else here asks you for anything, and if you never use that form the project holds no data about you at all.

What the LinkedIn application does

The project includes a LinkedIn application used for one purpose: publishing the daily edition to the project’s own LinkedIn Page. It posts the prepared text and the public edition as a PDF.

  • It writes only to the Page that owns the application. It does not post to any personal profile and does not post on anyone else’s behalf.
  • It does not read, store or process LinkedIn member data. It does not collect followers, connections, messages, profile details or engagement data.
  • Its access token is held in a file on the owner’s own computer and is never shared, transmitted elsewhere or committed to the source repository.

The newsletter

If you sign up, the morning edition is emailed to you: the front page, the lead story, what else is in the two pages, and links to read or download the PDF. One email a day, and nothing else. Every one carries an unsubscribe link, which takes effect immediately.

  • What is stored: your email address, and your answers to the two questions on the form (whether you want the print-ready PDF first, and whether you prefer plain text). Nothing else is asked for and nothing else is kept. There is no name field, and the project never asks for a postal address.
  • Who processes it: the list is held by Buttondown, which sends the email on the project’s behalf. Buttondown is in the United States; the project has its data processing agreement, under which transfers out of the EEA are governed by the European Commission’s Standard Contractual Clauses. The project is the controller of your address and Buttondown the processor.
  • What the project does with it: sends you the paper. The list is never sold, shared, published, or used to profile you, and it is not used to send you anything other than the edition. It is not committed to the source repository.
  • Delivery data: Buttondown records what it needs to deliver mail and may log bounces and, depending on its own settings, opens. The project does not use that data and does not build reader profiles from it. Buttondown’s own policy governs what it keeps.

Asking to be removed deletes your address from the list. Unsubscribing from any email does the same thing.

The owner’s own copy

Separately from the newsletter, the program emails the day’s post text to a single address belonging to the project’s owner. That is a message from the owner to the owner and involves nobody else’s data.

Sources

The paper is researched from public web pages and public GitHub release pages. It quotes and links to its sources; it does not republish them in full. Every item printed carries a link back to where it came from.

The code

The layout engine, the prompt and the publishing scripts are open source and can be read in full at github.com/braghettos/thedailyreconcile. Anything described on this page can be checked there.

Who is responsible

The paper is made by Diego Braga, who decides what it covers and runs the machine it is written on. For the newsletter list he is the data controller: the decisions about what is collected and why are his, and the questions below go to him rather than to a company.

Contact

Write to hello@thedailyreconcile.news to ask what is held about you, to have it corrected, or to have it deleted. Unsubscribing from any email does the deletion immediately and needs no request.

Questions about the code rather than about your data are better raised as an issue on the project repository.
